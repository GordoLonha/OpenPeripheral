# M65 RGB Elite — `1B1C:1B5A`

Same 64-byte "nxp" protocol as the K70 MK.2 (`07` write / `0E` read). Commands go out on
MI_01 `FFC2:0004`, replies come back on MI_00 `FFC2:0003`, buttons on MI_00 `FFC1:0002`.
Command layouts from OpenLinkHub's `m65rgbelite` driver (GPL-3.0-or-later); each one
below was checked on hardware on 2026-10-17 (firmware 3.41, bootloader 3.05).

| Bytes | Meaning | Status |
|---|---|---|
| `0E 01` → `0E 01 … ver(8) boot(10) vid(12) pid(14)` | firmware info | ✅ |
| `07 04 02` / `07 04 01` | software / hardware mode | ✅ |
| `07 22 03 01 02 r g b 03 r g b 04 r g b` | colours: `02` logo, `03` DPI indicator, `04` wheel | ✅ |
| `07 22 02 01 02 rgb 04 rgb` | only some zones: the others stay as they were (the DPI LED does **not** go back to firmware control) | ✅ |
| `07 13 02 00 n` | active DPI stage, n = 1..5 (0 = sniper) | ✅ |
| `07 13 (D1+s) 00 00 x_lo x_hi y_lo y_hi r g b` | define stage s (D0 = sniper) | ✅ (stage 1 = 200 DPI felt) |
| `07 0A 00 00 ms` | polling interval 1/2/4/8 ms; the mouse re-enumerates, like the K70 | ✅ (sysfs interval 1 → 8 → 1) |
| `07 13 04 00 v`, `07 13 04 01 v` | angle snapping off/on | accepted; effect not measured |
| `07 30 00 00 v` | button response optimization, 1 off / 2 on | accepted; effect not measured |

## Button remapping ✅ 2026-10-17
`07 40 08 00` + 8 pairs `[index, mode]`, index 1..8 = left, right, middle, back, forward,
DPI up, DPI down, sniper (bits 01..80 below, in order); mode `C0` normal, `40` host only.
**Then commit with `07 05 02 00 01`** (lighting/input control, `01` = mouse): without it the
modes do not take. Once committed, every button is reported in report `03`. Hardware mode
undoes it with `07 04 01` + `07 05 01 00 01`; the app first sets every button back to `C0`
(a host-only left button would leave the mouse unable to click if the app died).

## Buttons (report `03`, byte 1)
`0x01` left, `0x08` back, `0x10` forward, `0x20` DPI up, `0x40` DPI down, `0x80` sniper
(held) — confirmed; `0x02` right and `0x04` middle by order.

Sniper: with only software mode on, the firmware still slows down while the button is
held. Once the host has defined the stages (`07 13 D0..D5`), it no longer does, so the
app selects the sniper stage (`07 13 02 00 00`) on press and the previous stage on
release, as OpenLinkHub does (confirmed).

iCUE (video, 2026-10-17) also offers surface calibration and saving to the mouse's
memory: protocol unknown, needs a USB capture. In software mode the firmware still
changes the DPI itself, but the mouse never reports the stage, and in software mode the
DPI LED shows whatever the host painted. So the app follows the button presses, re-sends
the stage (`07 13 02 00 n`, clamped 1..5) so its count stays the truth, and paints the
indicator: 1 red, 2 white, 3 green, 4 purple, 5 cyan. The stage is kept in settings.
